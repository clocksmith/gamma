# Review of the BITS tooling, 2026-11-26: findings and what was done

Two reviews looked for one class of defect: places where a claim of "verified", "reproduced" or "holds" would
survive a real failure. **No finding changed a committed number or the outcome of a preregistered rule.** Five
sentences were false as written (four in the paper, one in a results page) and are corrected.

- **Review A:** a cloud code review of a snapshot of this folder and the paper's scripts (Gamma at `fec58bc20`).
  Ten findings. It did not rerun anything.
- **Review B:** a separate reviewer session started with the artifact paths and the list of A's findings, told to find
  what A missed. Fifteen findings, checked against Gamma `1bed0943d`.

Frozen files were not edited. Where a finding is in a frozen file, the gap is closed in a driver or a supplementary
checker, and the frozen run was checked from its receipts. See `RESEARCH_MAP.md`, "What is pinned and must not be
edited".

## What ran

- `python3 replay.py all --strict` from a clean clone on a second machine: all 19 steps pass in 109 s (check 5 s,
  score 36 s, train 59 s, posthoc 9 s). The first such run failed on two faults in the new checks themselves, which
  were then fixed (`4360c1148`).
- `python3 -B recheck_unseen_transfer.py`: passes in 43 s.
- `python3 test_chain_guard.py`, `python3 verify_bundle.py`: pass.
- `python3 run_replication.py` from a clean clone on a second machine, with the 288 retained chains copied in and the
  score cache removed: every chain accepted by the new receipt check, `results/codenet_results.json` regenerated
  identical to the committed file outside its timing fields (324 primary and 108 secondary cells), no exported
  dictionary changed, and `verify_bundle.py` passes on the regenerated results.

## A second session's audit of the fixes, and the three gaps it named

A separate session checked the ten Review A fixes at Gamma `4777ea49e`, found all ten closed, and reran the transfer
recheck, `replay.py check --strict`, `replay.py train --strict` and the chain-guard test. It named three gaps that
remain because frozen files cannot be edited. What was done about each:

| Gap | What can be done without editing a frozen file | Residual |
| --- | --- | --- |
| The frozen transfer checker, run alone, still prints its verdict, and the frozen README names only that checker | `witness-length-sweep-v1/VERIFY.md`, not frozen, says which command to run and why; this guide points to it | A reader who follows only the frozen README runs the weaker check |
| Padding and the time limit are enforced only when `replay.py` runs | Stated in the folder README and in the guide. No hosted CI job was added: the owner's rule is that automatic CI stays a smoke test | `independent_decode.py` and `train_arms.py`, run directly, behave as before |
| Any caller of the engine without a time bound can hang | The two remaining unfrozen callers, `rung2-presearch-v1/equal_budget_eval.py` and `rung3-archive-search-v1/evaluate_rung3.py`, now bound each run; their own test suites pass. The guide lists every caller | The frozen `fixed-source-v3` scripts and `train_arms.py` run directly are unbounded; their corpora are too small to fill the table |

## Still open

  far was an assistant session.
- The seed chains of the `fixed-source-v3` run cannot be checked from this repository.
- `fixed-source-v3/verify.py` (frozen) does not compare the `K` and `limit` fields of a chain's receipt; no unpinned
  checker was written for it.
