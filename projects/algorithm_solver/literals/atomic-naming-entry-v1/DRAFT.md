## Evidence and the distinct hypothesis

[Item27](../palette-names-v1/README.md) exposed only three multi-character names
under its frozen learned-entry/shared-binding rule; none was introduced. Its
strict-N coordinate source steps cannot install a new spelling that needs a
simultaneously paid dictionary entry. Its alternating joint arms did not propose
those hypothetical rewritten contexts to the dictionary search. That null does
not establish a universal palette failure.

[Item18](../character-objective-v1/FREEZE.md) already accepted lexicographic
objective/N/C/package improvements; at weight0 this includes N/C/package
plateaus. We do not present lex acceptance as new. Item18 froze source bytes.
The new question is whether a **single transaction changing safe binding colors
and one or two paid literal entries** reaches useful states that separate
source-only/dictionary-only transactions cannot admit. It can also merely
reclassify identifiers into multi-character codes without reducing actions.
Both effects must be visible and distinguished.

D10 is chosen using disclosed prior item30 results, not as confirmation:8,324
validation actions under both recorded policies, versus8,341 forD11. D10 was
not selected as successor because several incremental C/N checks failed. The
public item30 contract/FREEZE identifies D10 as the optional-character +4N
trajectory. Its public evidence records **256 entries,92 actual character
entries**, dictionary JSON SHA256
`3938578f4e3702f6c5a022746299f0e0076784c18bfc4ab91d0454b7cf4f4dcc`.
Do not restore96 characters. Preserve exactly the initial92 character entries;
this experiment does not add character-slot search. No actual character values
or private source/dictionary contents were read to prepare this draft.

## Concrete synthetic proof and limits

[proof.py](proof.py) invents eight programs, two owners for each of four parameter
names a/b/c/d. Each computes twice its argument plus a small local constant.
Use item13's actual binding records, unsafe/capture guard and rendering to rename
one parameter binding per program to `aa`, including all its references.
The dictionaries each have exactly256 entries; one/two unused **two-character**
entries are removed as appropriate. Short fillers prevent an isolated companion
move from appearing beneficial merely because it discards long stored strings.
All entries, original and replaced, remain charged. Every packet independently
decodes; all original/rewritten whole sources/bodies are banned.32 invented
behavior comparisons pass. A separate collision fixture rejects capture of an
unresolved `aa` reference. These are synthetic evidence, not corpus qualification.

All packages add the same13,010 decoder-source bytes for decoder-inclusive cost;
each program pays41 framing bytes, eight-bit selections and one Finish in actions.

All eight rename/no-rename × entry-subset combinations are scored. Renaming
with the context entry alone already lowers N72→64; adding the paid label lowers
it further to56. This is a source/dictionary-block barrier, **not a proof that
every entry in the two-entry bundle is necessary**.

The label-only atomic move wins lex(N,C,package) with unchangedN/package and
24 more source bytes. This is C reclassification, **not an action gain or a
successor**. The context atomic move lowers N and total package despite a larger
dictionary. Its isolated source and dictionary companions are nonimproving at
the specified same starting state/removals. The specified literal control is
useful and worse here, but is not the globally optimal literal neighborhood.
Other sequences, pruning, source groups or dictionary choices might bypass this
local barrier. No claim is made that private D10 is trapped or will improve.

Two focused tests pass. No source strings are taken from research corpora.

## Approved matched arms

All searched arms start from exactly D10's sources and dictionary. Fixed D10 is
also replayed. The intentional encoding order is (N,C,complete dictionary-ID
sequence), rather than canonical (N,IDs); all arms/references use this same
primary policy. Use the same shortest-minimum-character encoder and lex(N,C,
complete raw package) acceptance in every arm. No positive weighted objective
may increaseN. Only strict improvement of this three-part tuple is accepted;
source bytes and source/dictionary identities break ties between improving
candidates but do not admit a tied state.

| Arm | Permitted transactions |
| --- | --- |
| D | Dictionary only; source bytes remain D10 |
| S | Naming group only; dictionary remains D10 |
| A | Union of D and S transactions, evaluated separately |
| J | Same union plus atomic source-group/entry transactions |

A is necessary: J versusD/S alone confounds simultaneous admission with having
both mechanisms. J versusA isolates the added transaction family under common
objectives, proposal rules/caps, capacities and resource caps. As source and
dictionary trajectories diverge, their data-adaptive contexts/opportunities can
differ; J/A is a matched-procedure contrast, not identical later opportunities. The experiment does not claim
to isolate lex acceptance, which is held constant and already exists in18.
Record accepted N-improving, N-tied/C-improving and N/C-tied/package-improving
moves separately. Report exact singleton companion scores when evaluated and
unknown when not, including differing removal contexts. No accepted atomic move
alone proves a local barrier or general benefit.

## Approved bounded opportunities

Avoid a broad arbitrary source search. No compiler, syntax/algorithm rewrite,
recursive multi-binding repair or model is added.

1. **Common name list.** Fit-only D10 dictionary/binding records build the old27
   palette with its unchanged exclusions/rank; take at most its first four names.
   Add the fixed eight neutral names `aa,ab,ac,ad,ae,af,ag,ah` unconditionally,
   deduplicating. Thus at most12 targets, with eight proposed independently of
   learned-entry availability. All D/S/A/J arms receive the same list, sealed
   before validation. Existing guards still reject captures or unsafe sources.
2. **Common context list.** From each arm's current fit sources and exact selected
   literal segmentation, enumerate windows of2–6 consecutive selected pieces,
   at most160 bytes. A window must contain one or more **complete occurrences of
   one eligible binding** and must not cut any occurrence of that binding.
   Replace occurrences of that binding in the window by typed placeholder
   segments; other bytes remain literal. This tuple of literal/placeholder
   segments is a normalized context, e.g. binding-plus-binding. Rank contexts by
   distinct supporting program count descending, summed original selected-piece
   savings descending, normalized tuple. Keep16. At least two fit programs must
   support each context; no corpus-wide substring mining is added.
3. **Naming group.** For each of at most16 contexts ×12 targets, find its eligible
   matching bindings in the current fit sources. In each program choose at most
   one legal binding: most occurrences first, then binding ID. Rename all its
   declaration/reference spans with item13 `legal/render`; keep all other
   bindings unchanged. Programs with no legal match retain their current source.
   Non-ASCII programs also retain their source at fit and validation boundaries,
   preserving the inherited UTF-16/span safety guard.
   Require at least two changed program IDs. This bounds groups to192 per round,
   with at most one binding per program; it avoids combinatorial binding subsets.
4. **Paid entries.** Each opportunity offers (a) its literal target spelling,
   and (b) that spelling plus its rendered literal context. Remove already-paid
   entries; at most two entries are added. Require target/context length2–160,
   and context occurrence in at least two candidate rewritten programs. These
   are ordinary literal strings, never a substitution instruction or free alias.
   The two entry options give at most384 context-dictionary/atomic opportunities
   per round and at most192 distinct naming-only groups.
   Every arm sees the same generated opportunities/projection rules, including
   their dictionary-only projection on unchanged sources. They are not hidden
   from D/A merely because those projections often do not help.
5. **Ordinary dictionary control.** The same selected-piece proposer supplies up
   to24 fit-observed literal merges plus their first eight consecutive pairs.
   D/A/J offer these alongside the dictionary-only projections above. This is a
   small explicit control, not the entire historical30 dictionary pipeline.
6. **Capacity.** Protect exactly D10's actual92 one-character entries. Probe
   removal-only full-fit losses under the common tuple, keep the12 least harmful
   removable entries, including coverage-infeasible entries at the end. For
   one/two additions remove exactly `max(0,current_count+adds-256)` entries; rank
   combinations by summed N/C/package deletion loss then keys, test at most12.
   Score the entire panel after the full transaction; never infer feasibility
   or exact joint gain by adding deletion losses. No temporary >256 scoring,
   phantom characters, unused-argument subsidy or free label entry.
7. **Enumeration/budget.** Round-robin the ordinary dictionary, context-dictionary,
   naming-only and atomic streams in that order, skipping arms' unavailable
   streams. Deduplicate identical full source+dictionary states per round. A
   round accepts the best evaluated strict lex improvement. All arms use the
   same per-family caps and full-state evaluation budget,10,000 trials/
   600 seconds each, including deletion probes and failures. Four single-core
   workers use0/1/2/3,8GiB each, OMP/BLAS1. Use a hard3,600-second whole-job
   process-group guard covering preparation, fit, validation and qualification;
   the same four cores are reused by at most four qualification workers afterward. Atomic arms have
   more available transaction families, not extra evaluation slots. Report
   actual opportunity/transaction counts and timings; equal caps do not imply
   equal work. A bounded no-improvement stop is not global optimality.

The exact candidate/ranking/deletion procedure above is implemented;
execution still requires the separate FREEZE and cross-review. Coverage must be tested on the
selected dictionary's actual characters. An optional missing character cannot
silently return as a fallback. Existing full-source/solve-body bans extend to
every encountered candidate variant, including rejected ones, in all arms.
The ban set grows monotonically. If a newly encountered variant (even a rejected
one) contributes a whole-source/body string equal to an incumbent dictionary
entry, rejecting the transaction does **not** restore legality: preserve the
incumbent and new ban evidence, mark that arm audit-failed, stop its search and
block readiness. Do not drop the encountered variant from the ban set or remove
the incumbent entry for free. Other arms may finish, but a failed comparison arm
blocks the complete matched verdict. This explicit failure policy avoids an
undefined or silently narrowed ban universe.

## Validation transfer, sealing and qualification

Freeze source cohort, name-list construction, matching algorithm and budgets
before loading any private inputs. During execution, fit only on the existing
300IDs. Seal all four fit dictionaries, selected sources, target names, final
normalized context list, traces, accumulated bans and exact input identities
before validation values are hashed/loaded. Final contexts for each arm are
selected by the same fit-only16-context rule; do not choose them on validation.

D and fixed D10 retain unchanged D10 validation sources. S/A/J apply their sealed
name/context **rule** to each D10 validation source under their own fixed
fit dictionary, not the fit bindings' IDs/colors. At most two passes per source,
16 sealed contexts ×12 sealed target names per pass; enumerate matching legal
bindings with at most one rename per context/target transaction. Accept only a
strict per-source (N,C,packet bytes) improvement, with source bytes/text tie-breaks
between improving candidates. There is no dictionary mutation, new target-name
mining, context mining, aggregate-validation selection, source rescue or refit.
If a changed candidate lacks coverage, reject that proposed local move and retain
the already-covered incumbent, as the naming search does on fit. If the sealed
fit dictionary cannot encode the starting D10 validation source, retain the
coverage failure rather than searching for a validation rescue.

Per-source cost choice uses consumed validation inputs, as item13/27 did; it is
part of the frozen procedure and must be disclosed. It is not held-out independent
confirmation. Per-program policy transfer may produce novel source hashes; no
fit-specific color assignment or private source fragment is sent to a new ID.

Seal every final source choice before any cases execute. Reuse qualification
only from pinned passing **(problem ID,exact source hash)** receipts, including
D10's independent item30 evidence. Every genuinely new selected hash runs all
pinned cases with strict observation parity under the existing sandbox contract.
No name-safety assertion substitutes for qualification, and no retry, replacement,
repair or successful-hash cherry-pick follows failure. Preserve rejected attempts,
qualification failures, coverage failures and every denominator. The3,600-second global guard includes qualification; a timeout records
an incomplete no-verdict result, with no retries. Verify manifest/runtime metadata
before freezing this guard; this stage must not assume a small number of fresh
hashes or silently skip cases.
