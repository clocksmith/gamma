# Item56: coverage floor for one-owner entry budgets

Design, 2026-10-24. No private-input diagnostic is authorized by this draft.
Item50's accepted bound is positive only throughk2; it explicitly leaves the
coverage feasibility of those classes unknown. Resolve that interpretation
before treating a support-budget fraction bound as an achievable frontier.

For each original300-source cohort, let S contain every allowed exact string
occurring in at least two source IDs, including shared single characters.
Ignore the256-entry capacity and allow all of S simultaneously. Define r as the
number of sources that have no complete segmentation path using S.

Every covering dictionary must contain at least r one-owner entries. Each of
those r sources requires an entry outside S on its path; any allowed entry
outside S occurs in exactly one source and cannot serve a different source.
Choosing one such entry for each required source gives r distinct entries.
Thus k<r is coverage-infeasible, before the fraction or total-entry cap matters.
This is a necessary condition only. k>=r need not cover the cohort, fit256entries,
or attain10% character share. It is not the minimum achievable k.

A simpler subsidiary floor counts sources containing a character whose owner
set has size one. Any entry covering that character is one-owner. This floor
cannot exceed r in general. For these exact accepted50 inputs, it must equal r:
50 proves all96 characters belong to the old pool and no pool entry is banned.
A source without a private character therefore has a path of shared singletons;
one with a private character has no shared entry spanning it. Register equality
as an additional required identity check. Retain both independent reachability
implementations as a check, without claiming a stronger floor than character
ownership for this population. Banned-singleton invented fixtures exercise the
more general theorem, outside accepted50's eligible-input guarantees. Publish
no character or source text.

and report. No q, seed dictionary, combined400-source carrier, case, validation,

item23exit137 caveat; no fresh qualification or encoding result.

Production reconstructs pool occurrences with a trie in lexicographic
string-PID/start/end order, counts distinct owners per entry, filters shared
entries, and performs forward boolean reachability. Reconcile pool hash/count,
occurrence count/order digest and shared-entry count to accepted50. Source
hashes and original parser/body-ban digest also match accepted50. Absent alphabet
entries have zero occurrences and do not count as shared or one-owner.

Independent reporting reloads those same four exact files and parser bans,
reconstructs occurrences through the unchanged50Aho-Corasick matcher (explicit
shared implementation dependency), derives owner sets afresh, and performs
backward suffix reachability. Verify each recurrence at every position; prefix
and suffix vectors need not be equal. Compare complete-source path existence,
exact source success sets, owner counts,
shared IDs and occurrence digest. Tiny exhaustive substring/set oracles test
both implementations, repeated occurrences versus distinct owners, primitive
body exclusions, absent alphabet entries and gaps that shared substrings cannot
bridge. Both paths must agree exactly before publishing aggregate counts.

The accepted50 full universe and its checked shared-pool completeness are a
shared authority. This diagnostic does not re-prove the suffix index. Hash
identity plus accepted completeness and freshly rebuilt support establishes S;
matching entry counts alone would be insufficient.
