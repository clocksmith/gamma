# Fixed-D11 structured sidecar design

This draft implements the deferred2c branch of the [stack design](../stacking-v1/DRAFT.md).
The independent [draft freeze](FREEZE.md) is the execution/evidence contract.
No source binding, corpus probe or experiment has been performed.

Historical inclusion rationale: item5 prefix reduced R256 from9048 to9006 actions
(42), but had no demonstrated13 transfer and larger package16620 versus15255.
Item20 identifier templates reduced R from9048 to9015 (33), while naming rose
from8504 to8515 (11). Those are separate representation results, not gains that
can simply be added to flat13/24. A common literal/P/I language with a matched
searched literal control and single256-entry budget tests the actual interaction.
The fixedD11 output tests transfer after the flat stack's source and dictionary
changes. D11 is not assumed ready or superior before its completed record exists.

The implementation reuses the historical AST extractors unchanged, then supplies
a new common typed planner, new independently implemented Node decoder, matched
fit-only pool/search, source-bound runner, bounded supervisor and replay reporter.
No frozen historical module is edited. Prefix children exclude identifier
constructors; top-level body DP arbitrates their overlapping opportunities.
Optional-character coverage is preserved without restoring absent alphabet slots.
Synthetic tests cover roundtrip, malformed framing, precedence, forbidden nesting,
paid argument requirements, whole-body guards, depth, exact toy paths, both cache
invalidations, distinct-program support and fail-closed report gates.

Review questions before activation:

1. Confirm fixedD11 is the desired predetermined transfer cohort even if it is
   not item30's selected flat successor. A failed or unqualified D11 blocks this
   sidecar instead of allowing a substitute cohort.
2. Confirm the conservative generated-byte/whole-body guard and inherited
   structured readiness gates. These make the new language narrower than5/20;
   results cannot be relabeled historical replay.
3. Confirm a canonical minN policy is the proper matched causal comparison here;
   no mixed-policy comparison against item24 is proposed.
4. Inspect the independent decoder and planned source receipt binding. Complete
   item30 replay, an independently reviewed/pushed final freeze, and completed
   D11 hash binding remain outstanding before a corpus launch.

The current draft changes implementation inside the literals research component
while preserving parent intent: explicit representation/cost boundaries, exact
reconstruction, sealed fit, source-hash qualification, and retained failures.
It has no product API, engine, CLI, deployment, final-heldout or model-training
boundary effect. Offline search costs remain visible and no online solver claim
is made.

Focused verification: 19 synthetic tests pass, including a two-program four-arm
measure → stored packets → independent replay check, forged entry/decoder-cost
rejection, incomplete-supervisor reporting, and overlapping/empty conditional subsets with
full global overhead and retained coverage failures. Python syntax/imports, Node
syntax, CLI help and the unbound manifest hashes were checked. This does not
establish corpus runtime, numerical qualification or structured readiness.
