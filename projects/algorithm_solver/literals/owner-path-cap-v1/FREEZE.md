## Budgets, queue and failure behavior

Production and reporting are separately invoked phases, each capped at 1,200
seconds whole phase and 600 seconds per cohort. R uses core 6, naming core 7;
each process has 8 GiB RLIMIT_AS and one OMP/OpenBLAS/MKL thread. Queue behind any
prior core 6/7 job. The memory bound is per process, not a simultaneous aggregate.
The single approved invented measurement is evidence about its fixed invented
fixtures only; it provides no corpus ETA or performance-superiority claim.

Literal hard timers begin before local imports, argument parsing and contract
reads. Setup, input hashing, parser children, baseline reconstruction, index
checks, every schedule/allocation, serialization, log closure, normal group
cleanup and final publication count. Supervisors establish memory bounds before
worker creation; workers inherit them and reassert limits. No success after the
original phase deadline or before completed cleanup is accepted.

Every cohort is a separate process group. The supervisor kills/reaps descendants,
including parser children. A parser BaseException issues only nonblocking kill,
never a nested wait after an expired one-shot alarm. Normal cleanup has at most
10 seconds inside the phase window. First failure has one absolute emergency
bound <= first-failure+10 and phase-deadline+10; cleanup failure anchors it to that
cleanup's start. The bound is never reset across unlink/write/wait/log operations.

Hard BaseException deadlines propagate through failure handlers. A reporter
publication handler whose owner timer has expired skips local I/O and yields to
supervisor withdrawal under that same absolute emergency bound. Ordinary direct
I/O failures still remove success. Success markers are withdrawn before fallible
failure receipts. Fresh directories, no retries, truncation, partial predictions,
partial certificate promotion or post-timeout success are allowed.
