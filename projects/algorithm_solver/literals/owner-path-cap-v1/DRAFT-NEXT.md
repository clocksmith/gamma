# Item57 supplied-input implementation proposal

2026-10-24. This is premeasurement design, not a corpus freeze or permission to
open private inputs. Preserve DRAFT/proof/oracles. First build isolated in-memory
kernels and an independent checker, then review and pin one invented complexity
measurement. Any original-fit execution needs its own freeze and cross-review.

Keep the exact item53 q, suffix distances, denominator, entry universe, bans and
source identities. Reconstruct both accepted50/53 proofs, all257 rows and their
private top/potential/weight commitments. Never read a private53 result as an
input. Later authority would be the original28 nine-file allowlist and accepted
public53 report, not new source access.

Production may instantiate the unchanged53 Tighten reconstruction and invoke its
paired certificate, explicitly sharing that calculation. Build NEW top256 lists
for each owner: repeated one-owner groups stream every allowed new-only depth
and occurrence; unique groups use53's exact endpoint-minimum range splitting,
with a separate range heap and256 extractions per owner. Merge each owner's old
tightened weights separately. Shared weights stay exactly53. Inherited global
53 tops cannot supply these per-owner lists. Record all counts and top identities.

For each source position, derive the longest cross-owner prefix from the full
index's support>=2 intervals, including banned lengths before filtering edges.
An occurrence is one-owner exactly when its length exceeds that prefix. Obtain
banned endpoints from the checked full index. Compute R by a forward maximum
schedule: for each endpoint, inspect every preceding start, include its q53 if
one-owner and allowed, and compare with the free skip from the previous endpoint.
This processes all allowed one-owner occurrences, including entries omitted from
all top lists, with no complete edge graph or substring string materialization.
Keep only source-length schedule vectors. Count inspected and admitted edges.

Independent reporting must reconstruct original q order, d, weights and both
old proofs independently, as53's AC/end-order/reversed-DAG checker does; use an
isolated adaptation, not production results. Stream every allowed index-group
depth and accumulate owner-specific bounded sorted top lists. Shared Index and
accepted structural verifier are explicit shared dependencies.

For independent scheduling, use fresh AC occurrences of the complete old pool
and freshly counted owner sets to find each start's longest shared substring.
Build banned endpoints independently by matching all original banned strings.
Compute a BACKWARD maximum schedule over every outgoing endpoint, plus a free
skip. Compare source maxima, owner top identities/counts, all allocation rows
and digest-bound schedule recurrences; forward/backward vectors differ and must
not be compared for equality. Independent scalar allocation uses sorted owner
marginals, not production's next-marginal heap.

All entry ties use53's group/length identity. All owner ties use lexicographic
string source IDs, then marginal rank. Count finite available entries even when
weights or marginals are zero. Top256 per owner suffices only for allocation;
both maximum schedules must include every allowed occurrence. No forced-owner
coverage constraint or joint shared/one-owner cap is introduced.

Worst-case work remains quadratic or worse in total input length through full
allowed depth/occurrence enumeration. Peak storage includes original occurrences,
index/trie, bounded per-owner lists, source-length schedule vectors and independent
matcher data; no all-substring byte table or full new-edge graph. Explicit tiny
oracles compare q53, exact ownership/bans, both schedules, all257 bounds, top IDs
and weak duality. A later pinned invented measurement must include repeated-owner
strings, overlapping entries and enough owners to exercise per-owner top storage.
No corpus ETA, performance superiority or numerical gain follows from this design.
