# Authored-cohort empirical recognition v1

This is a separate measured classifier mode, not the conditional sound-schema
interpretation gate and not a proof of semantic uniqueness. Every one of the
4,081 known title/ID competitors participates, including protected and currently
unqualified identities. Only source-free metadata is embedded. Source availability
never filters scores or runner-up margins.

The policy family was frozen before evaluating the independently authored new
52-query development cohort. Twenty cosine/margin policies are compared, using
zero wrong positive acceptance and zero accepted controls first, then maximum
correct positive acceptance, then stricter thresholds. A separate28-query
confirmation cohort remains sealed until one policy is fixed. Neither cohort
reuses the earlier20-query diagnostic. Authoring is non-IID; a successful finite
18/20-positive, zero-wrong, eight-control-abstention comparison would not certify
population risk, all-catalogue coverage, or production deployment.

Queries supply text only to the encoder and decision. Expected identities, control
labels and evaluator contract declarations are not inference features. Truncation,
a score tie, insufficient confidence, or unavailable separately qualified JS/Python
metadata forces abstention. Accepted results expose their exact implementation
contracts and applicability caveat; inferred identity is not a universal domain
proof. No candidate source is opened or executed by this experiment.

The runner pins code, model/tokenizer/runtime/dependencies, policy and index bytes.
It writes resumable64-title chunks with identities, hashes, finite/unit-vector
checks, and progress. A two-thread native CPU process has900 CPU seconds,
1,200 wall seconds and8GiB address space limits, preceded by a native5GiB free
memory-headroom check. The previously approved4GiB provisioning disk ceiling is
not a RAM allowance. Model files and vectors remain private and out of Git.

Read the eventual aggregate receipt for results. A launch or partial index is
not recognition qualification. Historical goal1b and compact M1 outcomes remain
unchanged.

## Measured development outcome

The original900-CPU-second process completed all4,081 index vectors, then hit
its cap before a verdict. A separately authorized180-CPU/240-wall-second phase
reused the pinned cache and completed development in30.82 seconds. The chosen
policy accepted only1/40 positive queries correctly, with zero wrong/control
acceptances and51/52 abstentions. This fails useful coverage. All20 policy
outcomes and both resource phases are preserved in AGGREGATE-RESULT-v1.json.
The28-query confirmation cohort remains sealed; it was not consumed for a
predictably inadequate title-only representation. No recognition release pass.
