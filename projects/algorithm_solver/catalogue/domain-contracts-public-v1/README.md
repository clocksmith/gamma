## Source pin and limits

`source-pin.json` hashes the exact UTF-8 web-tool extraction response observed
for the six URLs, not the publisher's raw HTML. URLs, retrieval date and extraction
line references identify each clause. The response body is not redistributed;
these files contain compact authored summaries, not copied full statements.
The manifest hashes the authored JSON artifacts separately. Do not confuse
either digest with a permanently immutable upstream publication.

Before adoption, an independent reviewer must verify the cited clauses and
record any upstream drift. Input mutation, return alias identity and behavior
outside valid domains are unstated in these statements. Their null fields mean
unknown, not unrestricted or implicitly pure. Freeze explicit local policies
and their authority before effect qualification. Only 153 explicitly requires
logarithmic time; do not invent asymptotic official requirements for the others.
Resource limits chosen by a future judge must be labeled local limits.

## Integration gates

1. Review and version the contract, parameter order and all local policies.
2. Independently review the synthetic cases; use ordered comparison except
   916, which permits arbitrary output order but not duplicate result entries.
3. Bind the reviewed contract, adapter and exact JS/Python source identities to
   runtime, effect observations and test hashes. Expected outputs stay outside
   the approved native bwrap candidate sandbox.
4. Require independent receipts for promotion. Neither this source acquisition
   nor a finite synthetic pass proves universal correctness, complexity, current
   recognition, or full catalogue completion. Existing frozen compatibility and
   admitted-spec receipts retain their original scope and are not upgraded.
