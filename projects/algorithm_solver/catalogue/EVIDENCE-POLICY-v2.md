# Explicit admitted-contract evidence policy

The first bridge required `normative-typed-effects` receipts. That must not erase
existing independently verified source qualification under a narrower, explicitly
frozen admitted behavior/effect contract. Catalogue schema v2 therefore requires
an explicit evidence policy selecting accepted classes:

- `normative-typed-effects`: independently qualified against the pinned normative
  problem contract, still finite evidence rather than universal proof.
- `frozen-admitted-typed-effects`: independently qualified against the exact
  pinned admitted specification, including original reference behavior/effect
  observations where the historical contract declared them authoritative. This
  does **not** establish a broader normative domain.

Version1 remains normative-only. Version2 never enables compatibility-only probes.
Every admitted artifact must carry its exact contract scope and caveats in both
the independently verified receipt and returned implementation value; counts are
split by evidence class. An informal recognizer must not broaden applicability.
R1's source qualification can represent either explicitly selected class under
its actual pinned contract, but completion must disclose the evidence mixture;
recognition and current serving/runtime qualification remain separate.

A report summary or renamed flag is insufficient. The verifier adapter preserves
and rechecks source, ordered interface, runtime, tests, effects, original contract,
source-freeze and independently verified full-observation receipt identities.
Compatibility-only probes and unresolved domains stay blocked. No historical
receipt or verdict is edited. The external verifier remains the trust authority.

`materialize.py` provides an exact-file reader for later serving integration. It
checks immutable caller-authorized problem access, protected IDs, universe,
language, source and receipt bindings **before opening a source path**. It reads
only an explicitly located regular file beneath an authorized root, refuses
symlinks/traversal and enforces byte/hash limits. It never scans or decodes a
full source-bearing corpus before filtering. Successful materialization alone is
not runtime requalification, source execution or a serving release. Its policy
and locator manifest must themselves come from the existing authorized owner;
caller-supplied self-consistency does not manufacture access authority.
