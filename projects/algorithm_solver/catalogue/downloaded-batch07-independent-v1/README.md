# Batch seven independent qualification

This isolated assignment covers the 50 exact owner-provided JavaScript/Python
pairs in `authored/downloaded-general50-v1`. Original sources are preserved.
Historical protected Gamma source/test payloads are not inputs. This is an
exposed cohort, not a held-out or official judge acceptance claim.

`contracts.json` pins official public definition snapshots, ordered `solve`
interfaces, original source hashes and independently authored oracle strategies.
`cases.py` first checks the references against official examples, then adds new
exhaustive/seeded cases and mathematically checked legal maximum-size families.
Delivered expectations and cross-language agreement are not correctness oracles.
`test_oracles.py` cross-checks less direct references and rejection controls.

Full typed values are checked. Advantage Shuffle, Fair Candy Swap, matching-word
lists, parity sorting, digit-difference numbers, powerful integers and closest
points use their permitted predicate/multiset output freedom. Inputs remain
unchanged and mutable results must be fresh under the local service envelope.
This fresh-output requirement is stronger than the official point-output alias
requirements for 973. Alias failure here is local adapter evidence, not a claim
that returning existing point rows is forbidden by the original challenge.
Class Solution wrappers receive static delegation review only; their direct
execution is not qualified by this lane.

Every official input bound and relevant guarantee was reviewed, including
positive q for 858, odd pile total for 877, a guaranteed distinct-total candy
swap for 888, unique closest-point answer for 973, and the signed32 answer bound
for 945. In particular q=0 is not a legal counterexample under the pinned858
statement. Numeric arithmetic stays exact within Python integers / JavaScript's
safe-integer range for admitted cases; UTF-16/Unicode generalization is not
claimed beyond the ASCII problem domains. Optional follow-ups are not gates.

The freeze binds exact source/interface/effect/adapter/runtime/test/helper bytes,
limits and every batch before candidate execution. Candidate calls run one
interpreter at a time in the existing Linux bubblewrap judge: 1GiB address
space, three CPU seconds and eight wall seconds per bounded batch. Batch866
uses single calls so its large integer-search gap is attributable. Other large
argument packets also run singly; small batches repeat their first call for
state carryover. No expected result, statement or host oracle enters the sandbox.
Raw streams are flushed before verdicts. A failed setup stops the campaign;
there is no unsandboxed fallback. Public GPU/services are not interrupted.

`verify.py` separately reconstructs expectations and replays every raw result,
process status and digest, including failures. Finite passing cases are evidence,
not universal proofs. Code/result preparation, successful execution, source
review, qualification and catalogue promotion remain separate. Repairs, if
needed, must have distinct source identities and a new frozen run while all
original failures remain retained.
