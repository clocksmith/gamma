# Lawful authoritative-document expansion

Code-first representation successor, not an encoder experiment. `expand.py` reuses
`recognition_documents.build`, canonical catalogue validation and the existing live
boundary gate; no second statement authority or candidate-selection framework.

## Frozen first step: 54 -> 102 authoritative descriptions

1. Pin the existing 54-document plan and baseline, original title metadata/order,
   service v16 configuration/catalogue/receipts, and v11–v16 adoption status metadata.
2. Obtain identity additions from metadata only: 32 Easy, 8 Hard, 8 Medium; no source
   or statement payload is opened to discover IDs. Old 54 + new 48 = 102.
3. Live-authorize every selected ID for statement access before opening the combined
   catalogue. Adoption metadata does not itself establish semantic authority.
4. Validate existing catalogue/receipt authority, exact normative classification and
   each selected contract hash. Refuse missing authority or changes to the old54
   contract hashes. Other identities' semantic provenance is not inspected.
5. Emit a plan for the existing document builder. Its per-ID gate repeats before
   each later authority read and extracts only objective, result, domain and ordered
   interface. Source locators are never opened; no candidate/case is read or run.
6. Verify all 4,081 stable IDs and order remain, old54 text bytes are unchanged,
   exactly48 formerly title-only descriptions change, and remaining3,979 remain
   title-only. Protected482 and unknown727 remain competitors, not negative facts.

The intended authority snapshot is **service v16** with102 normative contracts.
Later adoptions require a linked new config, never silently refreshing the input
snapshot or retroactively changing historical54-document results.

## No automatic next-stage execution

This step only prepares authoritative descriptions and exact SHA-bound provenance.
It does not change cosine/margin policies, grammar, encoder, source qualification,
or ranking denominator. Availability is not a ranking filter. It creates no new
claim that informal descriptions are understood. The observed guard-v2 zero52
extraction-coverage result remains unchanged.

A subsequent encoder representation experiment must independently freeze complete
model/runtime/tokenizer/instruction/pooling/truncation/cache identities, enumerate
which document vectors change, retain all competitors and historical controls,
and receive main's execution approval. No training, downloads, encoder invocation,
evaluation or confirmation access is authorized by this plan.

## Synthetic checks

Seven owned tests cover complete identity union, overlapping/missing authority
metadata, gate denial before any combined payload, all-ID pre-open gate ordering,
unchanged old semantics, unchanged unknown titles and competitor retention.
They do not use query cohorts, model vectors, candidate sources or hidden cases.
