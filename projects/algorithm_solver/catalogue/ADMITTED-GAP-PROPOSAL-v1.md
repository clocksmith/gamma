## Target and authority

Independently qualify Python against the **same exact frozen admitted
return/type/mutation/alias specification** already bound to qualified JavaScript,
without claiming an official normative-domain specification or universal theorem.
Premium status neither establishes impossibility nor supplies missing authority.

The new [adapter](admitted_gap_adapter.py) is separate from
`python_receipt_adapter.py`; its `SCHEMAS` are unchanged. Old compatibility
reports, failures, and `qualified=0` remain immutable. The adapter never changes
the catalogue or service itself:

1. `reverify_original_report` checks externally pinned metadata/code/runtime and
   reruns the existing independent verifier on **every original report row and
   raw observation**, not a selected passing summary. Its existing transfer
   loader authorizes exact original400 IDs before any payload is opened. It
   executes verifier code, never candidates.
2. `review_gap` binds exact JS admitted receipts, Python sources/semantics,
   source freezes, run contracts, reports and raw verifier results. Tests,
   baseline observations, reference source, input manifest and case counts must
   equal the JS bindings. Runtime, harness, host oracle, comparison rules and
   full-observation verifier hashes remain bound. Typed returns, host-oracle
   acceptance, exact result, before/after arguments, alias edges and no-error
   requirements are all retained. A review emits **authored**, not qualified,
   candidates; absent/failed native evidence stays blocked.
3. `adopt_review` requires a separate owner/root-delegate approval, externally
   pinned to the exact review hash and explicit ready-ID subset. A caller's
   self-authored approval/hash is not authority. Only after that review can it
   produce new source-specific receipts. It grants no serving/publication rights.

The Python `problem_contract_sha256` is the existing JS admitted-contract digest,
not a newly weakened contract. Python-specific interface, runtime, effects,
source/sidecar, replay ancestry and approval remain independently receipt-bound.
Trusted pins, allowed IDs and local paths must be operator configuration, never
untrusted request fields. Full-observation verifier pins are external trust
inputs; this adapter cannot prove an operator's approval or attestations honest.
