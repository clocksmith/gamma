# Downloaded first batch: exposed qualification

This lane independently checks the exact 40 owner-provided programs imported by
`ef42d2023`, through their `solve` entrypoints. Import claims, cross-language
agreement, canonical admission, retrieval and held-out evaluation remain separate.
The supplied `Solution` wrappers are syntax-reviewed, not execution-qualified here.

The owner requested qualification after providing these sources. Ten IDs also
have historical protected reservations: 125, 414, 496, 561, 628, 693, 697, 709,
724 and 852. This new source-exposed cohort uses newly fetched official public
definitions and newly authored cases. Historical reserved sources and cases are
not inputs, and the reservation policy and canonical slots remain unchanged.

`oracles.py:validate` defines the accepted public input domains, including exact
integer bounds, printable ASCII, uniqueness, subset/permutation and mountain
preconditions. Argument order comes from the source import and official examples.
The official statement responses are retained privately under the ignored run
directory. Freeze receipts contain their URLs and hashes, not redistributed text.

The host compares full typed values. Two Sum accepts either ordering of its unique
pair; longest palindrome accepts any maximum palindrome substring; Keyboard Row
accepts any ordering while preserving multiplicity. Other outputs require exact
values and order. Every call must leave arguments unchanged and return fresh
mutable containers, an explicit local service effect envelope. String results
are immutable and may share storage. Numeric outputs stay within exact IEEE-754
integer range for these domains; Python's wider Unicode behavior is outside the
pinned ASCII contracts.

The reviewer read all 40 supplied sources independently of their author. They
contain ordinary algorithm code and wrappers: no file/network access, stdout
interference, imports, dynamic execution or observer/prototype replacement.
Counting Bits uses a shift/bit recurrence without builtin popcount. Mountain
Peak halves the interval on every iteration, meeting the mandatory logarithmic
requirement. Third Maximum sorts distinct values and does not satisfy its optional
linear-time follow-up. No optional follow-up is used as a mandatory gate. This
source review is not a formal complexity proof or a third-party acceptance.

`cases.py` builds official examples, exhaustive small cases, deterministic random
cases and legal domain boundaries, including maximum sizes. Delivered expected
outputs are not used. `test_oracles.py` cross-checks the less direct references
against exhaustive pairings, triples, stack operation paths and substrings; it
also tests wrong values, types, effects and aliases. Finite tests are evidence,
not proof over every legal input.

`qualify.py freeze` pins exact sources, helpers, cases, statements, runtime files,
commands and limits before execution. Each interpreter batch repeats its first
call to check state carryover. The existing bubblewrap judge provides private
namespaces and bounded CPU, memory, wall time and output. Only sources, observer
and argument packets enter the sandbox. Expected values stay on the host. A
failed sandbox setup must stop the run; there is no unsandboxed fallback.

`verify.py` separately reconstructs cases and replays every raw output, process
status and digest, including failures. Run identity is saved before launch and
batch checkpoints before dispatch; raw streams are saved before verdicts. The
authoring registry remains unknown until separate admission machinery consumes
appropriate receipts. These observations confer no official LeetCode acceptance.
