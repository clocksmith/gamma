# Remaining downloaded source qualification

This lane continues the owner-authorized qualification of exact downloaded
JavaScript/Python source pairs. The first 20-problem campaign is immutable.
All original deliveries remain separately committed. Historical protected Gamma
sources and cases are not inputs; these are new source-exposed cohorts with new
public definitions and independently authored cases. There is no held-out claim
or automatic canonical admission.

The current executable cohort is batch two: 68 IDs, 136 exact programs. Later
batches remain pending until their own independent reference cases and mandatory
constraints have been reviewed. Availability of source files is not qualification.

`cases.py` freezes new cases and checks independent references against official
public examples. `oracles.py` uses direct enumeration, combinatorics, predicate
checks and alternative algorithms. Supplied expected outputs and cross-language
agreement are not correctness oracles. `test_oracles.py` cross-checks the references
and rejection controls. Cases are bounded finite evidence; most array/string
cases exercise small inputs, rather than a claim to exhaust the full domain.

The canonical local `solve` API is a functional value adapter: inputs stay
unchanged, mutable outputs are fresh and nested aliases are rejected. This is
explicitly different from the official in-place wrapper ABI for 189, 283, 289,
324 and 344. Their supplied wrappers are not qualified here. Official wrappers
remain a separate execution gap; returned values cannot prove in-place behavior.

Mandatory numeric, algorithm and memory requirements are separate gates. The
original implementations of 7, 287, 378 and 386 and Python 371 have source-review
failures recorded even if their values pass. Sorting in 215 is reported as using
sorting; the wording asks whether it can be solved without sorting rather than
stating a mandatory ban. Optional follow-ups are not mandatory gates.

The freeze binds exact programs, definitions, generated cases, helpers and Linux
runtime files before any candidate runs. Expected outputs never enter the existing
bubblewrap sandbox. The run saves identity and batch checkpoints before dispatch,
then raw streams before judging. Missing sandbox setup stops execution. A separate
host replay reconstructs all expectations and compares raw outputs, process status
and digests. Execution of original sources preserves every failure; repairs, if
needed, must be new source identities with new frozen runs.
