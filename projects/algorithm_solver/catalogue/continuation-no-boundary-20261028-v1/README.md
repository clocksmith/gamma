# N/O boundary-repaired qualification lane

This lane holds the thirteen N/O problems whose case sets left review gaps: 3891, 3896, 3897, 3901, 3905, 3909, 3915, 3919, 3926, 3932, 3934, 3937 and 3942, each in Python and JavaScript (26 programs). The case set is every original N/O case for those problems plus new boundary cases from [boundary_cases.py](boundary_cases.py). A row whose arguments repeat an earlier row is dropped. That removes boundary rows that repeat original rows, and also 15 repeated rows inside the original 3897 set, so 3897 keeps its 107 distinct original cases.

Each new expected value comes from a method different from the cohort oracle, except 3937 (see below), and no candidate source is read:

**3937 reading.** Values may go below zero and `%` is the mathematical non-negative residue, so the cost to residue t from v is the circular distance min(|t − v mod k|, k − |t − v mod k|). The lane operator adopted this reading on 2026-10-28; it is not an owner decision. The cohort oracle and the O README use the same reading. External evidence: the public doocs reference for 3937 (https://leetcode.doocs.org/en/lc/3937/) uses this formula. That is a third-party claim, not a judge receipt. [test_boundary.py](test_boundary.py) checks that more than 20 boundary rows give a different answer under a non-negative-final reading (50 of the 501 do), so the rows separate the two readings. The 3937 reference enumerates final integers in [v−k, v+k] like the O cohort oracle; only its x ≠ y minimisation differs. Its independent cross-check is `circular_residue` in test_boundary.py, and the independent reviewer recomputed all 501 rows by a separate method with 0 mismatches.

**Other semantics** come from the cohort oracles and READMEs and were checked against the pinned statements on 2026-10-28: 3901 counts proper non-empty subsequences, 3919 breaks closest-index ties to the left, and 3926 concatenates chunks first and treats a hyphen as a joiner only between two letters. The new rows use only those readings and the same character classes as the original rows.

[test_boundary.py](test_boundary.py) checks each new reference against the cohort oracle on small inputs. It checks that each new reference reproduces every original row, including the analytic maxima. It also checks that every case validates against the cohort domain check, appears once, fits the unchanged transport envelope with no blocked case, and that no candidate source is loaded. The largest input packet is 2.43 MB and the largest projected output is 5.77 MB (3919), within the 16 MiB envelope. Every new 100,000-scale row is an isolated singleton batch.

**CPU estimate (claim, local model, not an executor receipt).** The heaviest rows are no larger than the original N/O maxima: n = q = 50,000 for 3901, 100,000 values for 3891, 3896, 3909, 3915, 3934 and 3942, and 100,000 cells for 3905. 3919 adds about 96,000 queries to a 100,000-value array. Separately written efficient JavaScript programs were run on the heaviest row of 3901, 3915, 3934, 3919 and 3905 under `node --jitless --single-threaded --max-old-space-size=256` on an Apple-silicon Mac. They are not candidate sources. Including JSON parsing and serializing the arguments twice, they used 0.07, 0.11, 0.43 (prefix-doubling suffix array), 0.05 and 0.08 CPU seconds, and matched the lane's references. I estimate that an efficient correct program stays below about 1 second, or a third of the 3-second limit, on the Linux executor. This was not measured there.

The protocol, the verifier, the limits, the observers, the gate handling, the pins-status check, the runtime binding, the review flags, the transport and the batch policy are the N/O lane's, restricted to these 26 programs. Comparison is exact for all thirteen problems, which all have exact return policies. The lane reuses the existing N/O refetched definitions.

Run on the Linux executor:

```
protocol.py review-template --gate G --gate-sha256 H --review NEW_REVIEW
protocol.py freeze --gate G --gate-sha256 H --statements NO_STATEMENTS --preflight LOG --preflight-sha256 H --review REVIEW --freeze NEW_FREEZE
protocol.py run ... --freeze FREEZE --freeze-sha256 H --output NEW_OUTPUT
protocol.py replay ...
```

Scope: exposed development finite cases only. There is no native wrapper, held-out, adoption or full-domain claim, and this lane changes no catalogue status.
