# Human composition input v1 on 128

The existing 256one typed workspace now accepts 0/1 operation/recipe choices,
explicit compatible argument bindings, signed integer/boolean constants, Return,
Undo and public Test. No model/source generation occurs in this human input path.
The broader typed language and autonomous composer remain separately accessible.

The first binary profile is `typed-composition-binary-v1`: eleven pure signatures,
two inspectable recipes, int/bool/List[int] parameters, at most 32 straight-line
steps. Other types and control/effect editing remain outside this bounded binary
candidate. The same challenge picker, difficulty ordering and ASCII/JS/Python
encodings are retained. The profile does not claim an optimal vocabulary.

App commit `739648386cc69475ee4e7e3530095bc11c6746d5`. [Implementation identities](implementation.json) bind the input mechanism and interpreter/recipe source bytes.

Source baselines use the recorded equivalent one-line function definitions and
unchanged eight-bit token profiles. Seven-bit ASCII costs for both sources also
appear in fixtures.json. Source costs exclude setup and Run; composition includes
binary Test and one Build action. They compare ideal input representation costs,
not measured time, corrections, full human trials or learned solving gains.
Recipe internals are reusable vocabulary, not free primitive work; this study does
not optimize or charge vocabulary-learning cost. Runtime input parameters come
from the selected challenge; each use still requires explicit binding bits.

[Execution receipt](execution.json) reports **1,974/1,974** checks. Integer pairs
cover -10 through 10; arrays enumerate lengths 0 through 5 over {-1,0,1}.
[verify.py](verify.py) calls the actual validated Gamma typed interpreter and frozen
recipe catalog, comparing with separately expressed arithmetic/list oracles.
The same implementing agent authored these fixtures/oracles: this is bounded
execution evidence, not an independently sealed evaluation or mathematical proof.
No checkpoint, model, training corpus, protected targets or hidden tests were read.

## Software checks and usage

37 existing judge/lane tests passed before execution. Focused Node checks cover
all five complete input streams, typed filtering, single-choice binding cost,
signed constants, invalid codes, undo, vocabulary/profile mismatch, corrupt replay
and deterministic reconstruction. Seven desktop/mobile/live browser checks passed:
new binary input and previous typed editor behavior, real sandbox add/heap-sort,
three existing examples, explicit insertion and stale-result rejection. Final
physical-input/vocabulary binding changes were checked again on desktop/mobile
and the live bridge. Local browser console/network checks were clean.

Open `http://127.0.0.1:8874/labs/two-button/`, select a challenge or authored example,
then Workspace > Build with 0/1. F/J (or configured keys), brackets/arrows, and the
touch buttons enter bits. No synchronous judge is needed to build/replay; testing
requires the paired loopback Gamma composition bridge. Public checks do not
establish independent correctness. The experiment records first public pass time,
logical entry actions and all observed key/pointer presses during the attempt.
Reading/setup before Build is explicitly excluded; playback timings are synthetic.

Export retains the full public problem and event history locally. Replay checks
profile plus full vocabulary and reconstructs final state/counters without running
code or changing the active build. It is a reproducibility check, not authenticity
or a fresh verdict. Existing source recordings are separate and untouched.

The app goal and `COMPOSITION_PLAN.md` require the next comparison to include
counterbalanced human attempts, reading from task reveal, complete setup/navigation,
corrections and separately authored correctness. Freeze the study and candidate
before evaluation; derive vocabulary revisions from measured whole-attempt costs.
