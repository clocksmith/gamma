## What this set can and cannot establish

The set deliberately broadens beyond the small set of development-description
families. That pre-output choice tests broader coverage, rather than only fresh
wording of existing curated profiles. It remains a small purposive sample,
concentrated in arrays and strings; tree/list object serialization is uncovered.
Some familiar example inputs overlap indexed examples, and the tiny independent
checks do not certify all behavior or asymptotic complexity.

Candidate routes have not run on this set. The current assisted selector is not
yet a complete automatic requirement-aware answer route. Before opening, finish
and development-test embedding-only, requirement selection, and selection with
clarification; freeze their code, profiles, thresholds, model/tokenizer, index,
budgets, environment and evaluator. Do not inspect these queries to implement
the missing behavior. Existing 24 descriptions remain development data.

Clarification replies describe requirements, not target identities. The evaluator
must reveal only requested information; unsupported questions receive `unsure`.
All routes start with the same input. For ambiguous cases, also compare a resolved
input control receiving the same predetermined information. Track confirmations,
questions and machine time separately from unmeasured human interaction time.

Score returned code against the user's independently reviewed requirements and
private checks. Correct identity selection without a returned checked program
is not an answer. Opening is one frozen scoring campaign; result-driven changes
require a new set. Keep composition's protected problems and aliases excluded.
