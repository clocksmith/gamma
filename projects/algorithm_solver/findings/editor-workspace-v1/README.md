# Two-button workspace integration

Component: algorithm_solver editor bridge. Intent deliberately extended to an
explicitly paired personal research interface; existing judge and held-out
boundaries preserved. Boundary effects: 256one owns static UI/typing/effort;
Gamma owns restricted challenge exports, bounded execution and known retrieval.

[Local receipt](local-journey.json) records an automated Chromium journey against
an SSH-forwarded Linux judge on host 128. It is not human productivity evidence.

- JavaScript Two Sum: 592 binary key events, exact source round trip, 3/3 public
  examples passed. Python: 648 events, exact round trip, 3/3 public examples passed.
- Gamma retrieval identifies `lc:two-sum`, shows source/license/Python language and
  3 public examples. Retrieval alone leaves the document untouched. Explicit
  insertion increments a separate solver counter, not manual press counts.
- Independent tests were not evaluated for these requests. These examples do not
  establish arbitrary-problem support or unfamiliar synthesis.

Acceptance evidence:

- Provisioned Linux: 48 focused judge/lane, editor execution/bridge and vocabulary
  checks passed. Active namespace cancellation removed task files and allowed
  the next job. Wrong results, CPU timeouts, output limits, host/network isolation,
  linked nodes, mutation and unsupported JS results were exercised.
- Follow-up challenge export and fixed-width fitting checks cover generated
  signature-only starters, absence of hidden/reference records, training-only
  shortcuts, exact byte cost and refusal to invent filler entries.
- 256one decoder tests cover all fixed-width IDs, complete source round trips and
  preserved legacy profiles. Browser tests cover mobile/desktop input, remapping,
  holds, previews, vocabulary, challenge navigation and exact request binding.
- Native macOS headless tests cover ASCII and the same JS byte codebook. Actual
  system-wide insertion into separate applications was not requalified.

The browser hashes the exact submitted JSON bytes; the bridge returns that hash.
Language, source, operation and problem all participate. A mismatched result is
rejected. Expected outputs remain in the trusted host, outside the candidate
namespace. Source statements/examples are an authenticated personal view with
license notices; the deployed catalog contains metadata only.

The bridge binds only to loopback and requires explicit pairing. The site does
not deploy a public runner. A phone can type without it, but cannot use a desktop's
loopback connection automatically. See [editor protocol](../../editor-protocol.md)
for setup, supported signatures and resource limits.
