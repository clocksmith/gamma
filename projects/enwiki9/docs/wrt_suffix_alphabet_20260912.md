# Suffix-related word codes with the strong predictor retained

The prior paid instruction replacement lost even before model bytes were counted.
This experiment applies its lesson: preserve the native backend behind the best
counted forecast, then change one representation it learns from.

Deliberately selected lenses 2 and 6 suggest a dictionary alphabet whose code
prefixes expose word relationships. The fixed treatment sorts dictionary words
by reversed spelling within slots [80, 3920) and [3920, end). The first 80 words
remain unchanged. Every word keeps its code length; vocabulary, word spelling
and the native backend remain identical. There is no corpus fitting or learned
permutation. A decoder can derive the mapping from the existing dictionary.

Class-based word prediction is established prior art; [Brown et al.](https://aclanthology.org/J92-4003/)
learn word classes from co-occurrence. This fixed spelling-based alphabet does
not implement that clustering algorithm and carries no global novelty claim.

The considered portfolio is:

- Another sparse hindsight replacement: reject unchanged because the prior
  [paid screen](paid_context_instruction_20260912.md) loses predictive strength.
- Learned semantic code assignment: park until a counted learner or compact
  mapping is justified; no model download or embedding training is authorized.
- Fixed suffix-related code assignment: select for an actual native archive
  comparison with the original and a shuffled dictionary ordering.

The old frequency-boundary swap changed code lengths and lost 1,140 archive bytes
on its matched 10M gate. Dictionary lexicographic packaging experiments restored
original ranks and concern a different mechanism. Neither establishes this
within-band coding-alphabet result.

Candidate `wrt_suffix_alphabet250k_q0_v2` freezes exposed raw [0, 250000).
P and K use byte-identical original dictionaries; D uses reversed spelling;
S uses a fixed SHA256 ordering within the same bands. All four arms use the exact
retained native backend, one OpenMP thread and the original pretraining dictionary.
P must reproduce the retained 44,958-byte archive and its complete SHA256 before
any changed-arm inference. Each arm encodes, independently decodes and reencodes.
P/K archive byte identity, exact inverses and byte-identical repeats are required.
The black-box screen does not claim internal predictive-state trace confirmation.

Source review found that dictionary order also affects pretraining. The never-run
v1 job was cancelled before execution; v2 explicitly supplies the original
pretraining dictionary to every arm. Neither v1's cancellation nor a future
resource failure is a compression loss. Completed partial artifacts are retained.

The bounded gate assigns CPU 2, 10,000,000,000 memory bytes, 67,108,864 scratch
bytes, zero swap and a 3,600-second elapsed stop. Allocator mode 0 avoids the
backend's file-backed allocations on the constrained shared root filesystem.
Retained-parent archive parity checks that this shared execution setting does
not change the comparison's parent archive.

Report g_P and g_S independently. Positive archive deltas still require actual
complete package costs and a separately frozen confirmation. The sorting source
is counted separately; Python/runtime and integration closure are not presumed
free. No sample result changes the 109,389,323-byte forecast. The full-corpus
score remains unknown against the 90,000,000-byte (9.0000000%) target.
