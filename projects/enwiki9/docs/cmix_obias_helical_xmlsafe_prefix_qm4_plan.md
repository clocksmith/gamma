# cmix-obias HELICAL XML-safe prefix QM4

## Question

Does the frozen, collision-verified raw far-history reservoir reduce an exact
`cmix-obias -e` archive after its individually described matches are restricted
to a representation that preserves the parent's XML and line parser geometry?

## Frozen transform

The development population is the first 250,000,000 canonical bytes. Candidate
copies come only from the frozen QM1 ledger. A copy is retained only when its
complete target is inside one `<text ...>...</text>` payload and the copied
target contains no CR, LF, `<`, or `>` byte. Sources remain exact, fully prior,
and closed. No anchor, source, distance, or length sweep is permitted.

The transform emits literal gaps plus a restricted paid ledger. Its inverse
reconstructs the exact prefix chronologically. The unchanged XML delimiters and
line separators keep article boundaries, redirect classification, and line
geometry available to the ordinary `cmix-obias -e` preprocessing path.

## Matched backend gate

Encode the exact original prefix and exact residual with the same host-native
`cmix-obias` package, head blob, residency setting, working-directory shape,
and termination path. Decode both self-extracting archives. The baseline must
reconstruct the original directly. The residual archive plus restricted ledger
and counted inverse must reconstruct the same original.

The finite discovery delta is:

```text
baseline archive9 bytes
- residual archive9 bytes
- restricted ledger.lzma bytes
- incremental compressed inverse/source bytes
```

Positive archive displacement is required before any distant or larger replay.
No average-rate estimate, copied-byte count, or external public archive earns
score credit.

## Kill conditions

- XML/line-safe selection exposes no substantial copied population.
- Either exact reconstruction fails.
- The residual backend crashes or changes dependency requirements.
- The fully paid matched delta is non-positive.
- Memory exceeds the official decimal ceiling.
