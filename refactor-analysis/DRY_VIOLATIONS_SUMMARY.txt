================================================================================
  GAMMA PROJECT - DRY VIOLATIONS ANALYSIS SUMMARY

ANALYSIS DATE: 2025-10-17
SCOPE: Engine implementations (src/engines/), Core modules (src/core/)
FILES ANALYZED: 13 engine implementations

================================================================================
  CRITICAL FINDINGS
================================================================================

1. MASSIVE TOKEN HANDLING DUPLICATION (~200 lines across 9 files)
   Location: Every engine file has get_token_text() method
   Files: pytorch_engine.py, jax_engine.py, llama_cpp_engine.py, 
          tensorflow_engine.py, mlx_engine.py, onnx_engine.py, 
          pytorch_cuda_engine.py, mlx_gpu_engine.py, ollama_engine.py
   
   Issue: Nearly identical 15-25 line method duplicated 9 times
   
   Impact: One bug fix requires changes in 9 places
   
   Solution: Move to LLMEngine base class in engine_interface.py (1 location)

2. KV CACHE HANDLING - 6 REPEATED METHODS (~200+ lines across 8 files)
   Methods affected:
   - get_kv_cache_shape()
   - bridge_kv_cache_to()
   - export_kv_cache_state()
   - import_kv_cache_state()
   - append_to_input()
   - get_device()
   
   Each engine implements these with 95% identical code
   
   Solution: Extract to abstract base class with minimal overrides per engine

3. LOGITS PROCESSING PIPELINE DUPLICATION (~100+ lines across 10 files)
   Pattern: Every engine's predict_next() repeats:
   - temperature_scale()
   - top_k_filter()
   - top_p_filter()
   - softmax()
   - argmax()
   
   Despite sampling_utils.py having these functions, the call pattern
   is duplicated in each engine
   
   Solution: Create process_logits_for_sampling() in sampling_utils.py

4. MODEL/TOKENIZER LOADING DUPLICATION (~120 lines across 6 files)
   Repeated pattern in load() methods:
   - AutoTokenizer.from_pretrained()
   - Gemma model special handling
   - Model quantization setup
   - Error handling
   - _populate_special_token_map() calls
   
   Solution: Extract to _load_hf_tokenizer() and _load_hf_model() base methods

5. PyTORCH/PyTORCHCUDA ENGINE DUPLICATION (Critical)
   PyTorchCUDAEngine duplicates PyTorchEngine code
   Instead of inheritance, it appears to be a parallel implementation
   
   Solution: Make PyTorchCUDAEngine inherit from PyTorchEngine,
            override only GPU-specific methods
